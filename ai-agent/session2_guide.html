P1상황을 설명하고 설계를 시킨다8분

일을 시키기 전에 일을 이해시킵니다. 첫 응답은 “실행”이 아니라 “계획”으로 받습니다.

나는 PR 대행사에서 일한다. 지금부터 이 폴더를 하나의 업무 프로젝트로 만들려고 한다.

[상황]
- 고객사: NOVA LABS Korea / 브랜드: MORNING DEW
- 신제품 Barrier Glow Mist 60ml 를 2026년 9월 15일에 출시했고,
  9월 15일 ~ 10월 31일 캠페인을 집행 중이다.
- 오늘은 2026년 10월 2일, 캠페인 2주차다.
- 내 업무: 매주 온라인 반응을 수집·분석해 주간 리포트를 만들고
  고객사 담당자에게 메일로 보낸다. 이걸 매주 반복한다.

[내가 쓸 도구]
- 네이버 검색 API (뉴스·블로그·카페)
- YouTube Data API (영상 조회수·좋아요·댓글)
- Google Drive (리포트 저장·공유)
- Gmail (요청 접수·회신)

[지금 폴더에 있는 것]
- 브랜드코어.md, 캠페인개요.md

이 업무를 매주 반복할 수 있는 프로젝트 폴더로 만들려고 한다.
아직 아무것도 만들지 말고, 먼저 아래를 제안해줘.
1) 어떤 폴더와 파일이 필요한지, 각각 왜 필요한지
2) 그중 지금 당장 필요한 것과 나중에 만들어도 되는 것
3) 내가 결정해줘야 하는 것이 있다면 질문 3개 이내로
  • 파일을 바로 만들지 않고 제안부터 했는가
  • data / output / scripts 같은 구분을 제안했는가
  • 지시서 파일(AGENTS.md)의 필요성을 언급했는가
사람마다 다른 구조가 나옵니다. 정답 구조는 없고, 설명할 수 있는 구조가 좋은 구조입니다.
P2구조를 만들고 지시서 초안을 받는다7분

지시서를 백지에서 쓰지 않습니다. 자료를 읽혀 초안을 받고, 판단이 필요한 칸만 내가 채웁니다.

좋다. 제안한 구조대로 폴더와 빈 파일을 만들어줘.
그리고 AGENTS.md 초안을 아래 6개 항목으로 작성해줘.

1. 이 폴더는 무엇을 하는 곳인가
2. 너의 역할
3. 작업 절차 (수집 → 분석 → 리포트 → 저장 → 회신 초안)
4. 자료 사용 규칙
5. 금지 사항
6. 출력 규칙

내가 채워야 할 부분은 (미정)으로 남겨두고,
캠페인개요.md와 브랜드코어.md를 먼저 읽고 거기 있는 내용은 반영해줘.
없는 내용은 지어내지 말고 (미정)으로 둬.

그리고 CLAUDE.md 는 AGENTS.md 를 따르라는 한 줄만 넣어줘.
  • 금지 표현(피부과 시술 대체 등)이 5번 항목에 들어갔는가
  • 성과 우선순위(저장 > 댓글 의향 > 유입 > 조회수)가 반영됐는가
  • 읽지 않은 내용을 지어내지 않고 (미정)으로 뒀는가

너무 길고 추상적이면

AGENTS.md가 너무 길고 추상적이다.
각 항목을 3줄 이내로 줄이고, 판단이 필요한 문장은 전부 (미정)으로 바꿔줘.
P3자료를 읽히고 첫 결과를 만든다5분

API도 스크립트도 없는 상태에서 “이 폴더가 일을 한다”는 감각을 먼저 확보합니다.

아직 API는 연결하지 않았다.
지금 폴더에 있는 자료만 읽고, 이번 주 리포트를 만들기 위해
내가 무엇을 수집해야 하는지 정리해줘.

1) 수집해야 할 검색 키워드 목록 (우리 브랜드 / 카테고리 / 사용 맥락 구분해서)
2) 각 키워드를 어느 채널에서 수집할지
3) 리포트에 들어갈 항목 목록과 순서
4) 클라이언트가 중요하게 본다고 자료에 적힌 지표

자료에 없는 내용은 지어내지 말고 [확인필요]로 표시해줘.
  • 4번에 “저장 수 → 구매 의향 댓글 → 자사몰 유입 → 조회수” 순서가 나왔는가
  • 3번 리포트 항목 순서가 그 우선순위를 반영했는가
  • [확인필요]가 실제로 등장했는가
P4네이버 API 키를 발급받는다12분

에이전트를 1:1 안내자로 씁니다. 마지막 문단이 핵심입니다 — 콘솔 화면은 수시로 바뀌고, 에이전트가 기억에 의존하면 없는 버튼을 누르라고 합니다.

네이버 검색 API를 쓰려면 Client ID와 Secret이 필요하다고 들었다.
내가 직접 발급받으려고 한다.

한 번에 한 단계씩만 안내해줘. 내가 "다음"이라고 하면 다음 단계로 넘어가줘.
화면에서 뭘 눌러야 하는지, 뭘 입력해야 하는지 구체적으로 알려줘.

중요:
- 확실하지 않은 화면이나 버튼 이름은 지어내지 말고
  "화면이 다를 수 있으니 보이는 대로 알려달라"고 물어봐줘.
- 내가 화면을 설명하면 그걸 기준으로 다음 단계를 안내해줘.
  • 한 번에 한 단계씩 안내하는가
  • 모르는 화면을 지어내지 않고 되묻는가
  • Client ID / Secret 두 개를 모두 확보했는가
12분을 넘기면 조교에게 예비 키를 받고 다음으로 넘어가세요. 키를 못 받아도 실습은 계속됩니다.
P5키를 안전하게 넣는다3분

에이전트에게 키 값을 채우게 하지 않습니다. 자리만 만들게 합니다.

발급받은 Client ID와 Secret을 이 프로젝트에서 쓰려고 한다.
키를 안전하게 보관하는 방법을 설정해주고, 내가 뭘 해야 하는지 알려줘.
키 값 자체는 네가 만드는 파일에 직접 쓰지 말고,
내가 넣을 자리만 만들어줘.
P6Drive · Gmail 커넥터를 연결한다5분

앱 설정에서 커넥터를 연결합니다. 권한 동의 화면을 읽고 승인하세요 — 에이전트에게 권한을 주는 순간입니다.

Gmail과 Google Drive가 연결됐는지 확인해줘.
Gmail에서 최근 메일 5건의 제목만 보여주고,
Drive에서 내가 접근 가능한 폴더 3개만 알려줘.

P7수집 스크립트를 만들게 한다12분

파이썬을 못 써도 파이썬 도구가 생깁니다. 여러분이 하는 건 요구사항을 적는 것뿐입니다.

네이버 검색 API로 데이터를 수집하는 스크립트를 만들어줘.

[요구사항]
- 뉴스, 블로그, 카페 세 종류를 각각 검색할 수 있을 것
- 검색어와 종류를 인자로 받을 것
- 결과는 data/raw/ 아래에 JSON으로 저장할 것
- 개인이 쓴 글(블로그·카페)은 제목, 링크, 본문 2줄 발췌까지만 저장할 것
  (본문 전체는 저장하지 않는다)
- 실행하면 몇 건을 수집했는지 화면에 알려줄 것
- 키는 .env에서 읽어올 것

만들기 전에 어떻게 만들지 3줄로 먼저 설명해줘.
규칙이 코드가 되는 순간 — “본문 전체는 저장하지 않는다”가 규칙이 아니라 코드가 됐습니다. 규칙은 어길 수 있지만 코드는 못 어깁니다.
P8-1검색어를 함께 설계한다4분

검색어를 정하는 게 이 업무의 절반입니다.

수집할 검색어를 정하려고 한다. 캠페인개요.md를 읽고 아래 세 묶음으로 제안해줘.

1) 우리 브랜드 — 우리 제품을 직접 가리키는 검색어
2) 카테고리 — 우리 제품이 속한 제품군을 사람들이 실제로 검색할 법한 말
3) 사용 맥락 — 우리 타깃(25~34세 직장인 여성)이 이 제품을 찾게 되는 상황

각 묶음마다 3~4개씩, 왜 그 검색어인지 한 줄 이유를 붙여줘.
그리고 각 검색어에서 우리와 무관한 결과가 섞일 가능성이 있으면 미리 알려줘.

P8-2실제로 수집한다4분
정한 검색어로 수집해줘. 채널은 아래처럼 나눠서.

[우리 브랜드] 모닝듀 / 배리어 글로우 미스트 → 뉴스, 블로그
[카테고리]   수분 미스트 / 페이스 미스트 / 미스트 추천 → 블로그, 카페

수집이 끝나면 검색어별 건수를 표로 정리해줘.
0건인 항목은 0건이라고 그대로 적어줘.
그리고 우리 제품과 무관해 보이는 결과가 있으면 몇 건인지, 어떤 종류인지 알려줘.
0건이 정상입니다. 신제품이라 아직 언급이 없습니다. 0건인데 리포트에 내용이 있다면 그건 지어낸 겁니다.
P9지시서를 내 손으로 정교화한다15분

괄호 안은 자기 말로 채웁니다. 여기서 시간을 씁니다.

AGENTS.md를 고치려고 한다. 아래 내용을 반영해줘.

[분석 규칙 추가]
- 논조 분류 기준: 긍정 / 중립 / 부정을 어떻게 나눌지 기준을 명시한다.
  (내 기준:                                    )
- 우리 브랜드 언급이 0건이면 "0건"이라고 쓴다. 추정하거나 채우지 않는다.
- 카테고리 데이터는 우리 브랜드 성과로 쓰지 않고, 시장 맥락으로만 쓴다.
- 우리 제품과 무관한 미스트(헤어·룸 스프레이·가습기 등)는 집계에서 제외하고,
  제외한 건수와 이유를 리포트에 남긴다.

[출력 규칙 추가]
- 모든 수치와 인용에는 (파일명, URL)을 함께 표기한다.
- 성과 지표는 저장 → 구매의향 댓글 → 유입 → 조회수 순으로 배치한다.
- 리포트 마지막에 '사람이 확인할 것' 3개 이상을 붙인다.

[금지 사항 추가]
- 브랜드코어.md의 금지 표현은 우리가 쓰지 않는 것은 물론,
  수집한 글에 그 표현이 있어도 리포트에 그대로 인용하지 않는다.
  인용이 꼭 필요하면 표현을 바꾸고 원문 링크만 남긴다.
- 경쟁 브랜드와의 직접 비교 문장은 인용하지 않는다.
- 리포트에 실존 브랜드명이 등장하면 '경쟁사 A', '경쟁사 B'로 바꾼다.
P10리포트 v1 · 그리고 짝과 바꿔본다10분

data/raw/ 안의 자료만 사용하고, 없는 내용은 [확인필요]로 표시해줘.
output/ 에 저장해줘.

옆 사람의 AGENTS.md를 받아서

그리고 방금 만든 내 리포트와 무엇이 달라졌는지 5줄로 비교해줘.
데이터는 같았습니다. 지시서만 바뀌었는데 리포트가 달라졌습니다. 오늘 만든 건 리포트가 아니라 지시서입니다.

P11YouTube API 키를 발급받는다20분

마지막 질문을 반드시 넣으세요. 결제 안내 화면이 GCP 발급의 최대 이탈 지점입니다.

YouTube Data API로 데이터를 수집하는 스크립트를 만들어줘.

[요구사항]
- 검색어로 영상을 찾고, 각 영상의 조회수·좋아요 수·댓글 수를 가져올 것
- 상위 영상들의 댓글 본문도 가져올 것
- 댓글에서 작성자 이름과 채널 정보는 저장하지 말 것 (본문만)
- 결과는 data/raw/ 에 JSON으로 저장할 것
- 키는 .env에서 읽어올 것

[중요 — 쿼터 절약]
- search.list는 1회에 100 units, videos.list와 commentThreads.list는 1 unit이다.
  하루 한도는 10,000 units다.
- 검색 호출은 최소로 하고, 영상 통계는 ID를 모아 한 번에 조회하도록 설계해줘.
- 실행할 때마다 이번 실행이 몇 units를 썼는지 화면에 출력해줘.

만들기 전에 쿼터를 어떻게 아낄 건지 먼저 설명해줘.
호출용도비용
search.list영상 검색100 units
videos.list조회수 · 좋아요 · 댓글 수1 unit
commentThreads.list댓글 본문1 unit
검색 3회 + 통계 1회(영상 50개) + 댓글 20회 = 약 321 units — 하루 한도 10,000의 3%입니다.

수집 후 아래를 정리해줘.
1) 영상별 조회수·좋아요·댓글 수 표
2) 댓글에서 구매 의향이나 사용 문의로 보이는 댓글의 비율
3) 반복적으로 등장하는 표현 5개

주의:
- 조회수 순이 아니라 댓글 의향 비율 순으로 정렬해줘.
  (클라이언트가 중요하게 보는 지표 순서다)
- 광고 표시(#광고, 유료 광고 포함)가 설명란에 있는지 함께 표기해줘.
  • 조회수가 아니라 의향 비율로 정렬했는가
  • 광고 표시 여부를 표에 넣었는가
  • 동일 문구가 반복되는 댓글을 별도로 언급했는가
