① PRD 초안

목표: 기능 이름을 나열하는 대신, 사용자가 할 일과 합격 조건을 정합니다.

단계별 프롬프트
프로젝트의 problem-definition.md를 읽고 작은 PoC의 PRD.md 초안을 작성해주세요.
이번 단계에서는 문서만 작성하고 구현하거나 외부 서비스에 연결하지 마세요.

먼저 핵심 정보가 충분한지 확인해주세요.
입력 데이터, 원하는 출력, 판단 기준, 데이터 사용 권한 중
구현 방향을 바꾸는 정보가 빠져 있다면 핵심 질문을 최대 3개씩 해주세요.
그 밖의 미확인 정보는 임의로 채우지 말고 미확인 항목에 남겨주세요.
사용자가 말한 사실, 추정, AI의 제안을 구분해주세요.

PRD에는 다음을 포함해주세요.
1. 문제와 배경: 문제정의서의 어느 문제를 해결하는가
2. 현재 업무 흐름과 목표 사용자
3. PoC 목표와 핵심 사용자 시나리오 하나
4. Input: 형식, 필수 정보, 허용된 데이터 범위
5. Process: AI가 할 작업과 사람이 할 판단
6. Output: 형식, 필수 항목, 근거 표시 방식
7. 업무 규칙과 예외: 누락·모호·잘못된 입력을 어떻게 처리할지
8. In Scope와 Out of Scope
9. 데이터·권한·비용 제약과 금지 행동
10. 요구사항 표: ID / 요구사항 / 원래 문제와 연결 / 합격 기준
11. 성공 지표: 현재 수준 / 목표 초안 / 측정 방법 / 표본 / 검토자
12. 테스트 방법과 정상·경계·오류 사례
13. 미확인 질문과 결정이 필요한 항목

요구사항 ID는 R-01처럼 붙이고 합격 기준을 관찰 가능한 문장으로 써주세요.
문제정의서에 없는 기능을 추가하지 마세요.
새 목표 수치는 제안임을 표시하고 내가 확인하기 전 확정하지 마세요.
현재 수준을 측정하지 않았다면 미측정으로 남겨주세요.
문서 상태는 '초안'으로 표시해주세요.

사람의 확인: 내 문제가 맞는지, “정확하게·빠르게”가 구체적인 기준으로 바뀌었는지, 이번에 하지 않을 일이 있는지 확인합니다.

다음 기준으로 문제점 / 영향 / 수정 제안을 표로 보여주세요.
- 문제정의서의 실제 문제와 요구사항이 연결되는가
- 핵심 기능 하나를 수업 시간 안에 검증할 수 있는가
- 입력과 출력, 누락 정보의 처리 방식이 명확한가
- 사람이 판단할 일과 AI가 할 일이 구분되어 있는가
- 범위 밖 기능과 외부 연결이 끼어들지 않았는가
- 합격 기준을 테스트로 확인할 수 있는가
- 데이터 사용이 허용되고 비밀정보를 요구하지 않는가
- AI가 임의로 정한 수치나 업무 기준이 있는가

③ 구현계획

implementation-plan.md에는 다음을 포함해주세요.
- 전체 흐름: 입력 → 처리 → 사람 확인 → 결과 저장
- 최소 프로젝트 구조와 파일별 역할
- AGENTS.md에 둘 작업 규칙과 금지 행동
- context에 둘 업무 기준과 참고 지식
- 반복 절차를 Skill로 분리할 필요가 있는지와 이유
- 필요한 스크립트·도구·실행 환경과 준비 상태
- 작업 표: Task ID / 연결된 요구사항 ID / 작업 / 선행 작업 / 완료 확인
- 네트워크나 인증이 실패할 때 사용할 안전한 샘플 경로

Skill이 필요하면 현재 도구에서 지원하는 위치와 인식 방법을 확인할 항목으로
표시해주세요. SKILL.md 파일을 만들기만 하면 자동 인식된다고 가정하지 마세요.

test-plan.md에는 구현 전에 고정할 테스트 조건을 작성해주세요.
- 요구사항 ID와 테스트 ID 연결
- 정상, 경계, 정보 부족, 판단 모호, 잘못된 입력 사례
- 외부 텍스트 속 명령문을 지시로 따르지 않는지 확인할 사례
- 입력, 기대 결과, 합격 기준, 사람이 검토할 부분
- 업무 시간 측정이 필요하면 AI 처리와 사람 검토·수정시간을 포함한 측정법
- 연습에 쓸 사례와 수정 후 최종 확인에 남겨 둘 사례 구분

기대 결과는 초안으로 표시하고 구현 전에 내가 검토할 수 있게 해주세요.
권한·비용·설치가 필요한 항목은 필요 이유와 대안을 먼저 알려주세요.

사람의 확인: PRD의 모든 핵심 요구사항이 작업과 테스트로 이어지는지 확인합니다. AGENTS.md는 작업 규칙, Context는 업무 지식, Skill은 필요할 때 재사용할 절차로 구분합니다. 요구사항 전체를 세 파일에 복사하지 않습니다.
